# AI Engineer Levels Overview

## Purpose
Defines the capabilities and limitations of AI Software Engineers at different maturity levels (L1-L4), providing clear expectations for what each level can accomplish and guiding users in selecting the appropriate level for their project needs.

## Key Concepts
- **Level Progression**: L1 (Junior) → L2 (Mid-Level) → L3 (Senior) → L4 (Staff)
- **Capability Mapping**: Each level maps to human engineering experience ranges
- **Skill Domains**: Core implementation, security, distributed systems, production readiness
- **Project Complexity**: Different levels handle different project scales and complexities
- **Evaluation Alignment**: Levels correspond to the evaluation suite projects

## Level Definitions
1. **L1 - The Builder (Junior)**
   - 0-2 years equivalent experience
   - Can build functional applications from specs
   - Cannot handle complex architectures or security
   - Suitable for prototypes, MVPs, simple tools

2. **L2 - The Secure Builder (Mid-Level)**
   - 2-5 years equivalent experience
   - Adds security, auth, and robustness
   - Cannot design distributed systems
   - Suitable for production multi-user apps

3. **L3 - The Architect (Senior)**
   - 5-10 years equivalent experience
   - Masters distributed systems and microservices
   - Cannot handle extreme compliance/scale
   - Suitable for complex platforms

4. **L4 - The Production Engineer (Staff)**
   - 10+ years equivalent experience
   - Handles compliance, scale, and complexity
   - Full production readiness
   - Suitable for enterprise systems

## Relationship to Complexity Scoring
- L1 projects typically score 0-3 complexity points
- L2 projects typically score 4-5 complexity points
- L3 projects typically score 6-8 complexity points
- L4 projects typically score 9-10 complexity points

## Evaluation Suite Alignment
- Level 1 Eval: PDF Converter → Tests L1 capabilities
- Level 2 Eval: Task Tracker → Tests L2 security skills
- Level 3 Eval: Collaboration Platform → Tests L3 distributed systems
- Level 4 Eval: Trading Platform → Tests L4 production readiness

## Usage Guidelines
- Start with the lowest level that meets requirements
- Don't over-engineer - simpler is often better
- Consider progression - can start low and upgrade
- Match level to project criticality

## Key Capabilities by Level

### L1 Capabilities
- CRUD operations
- Basic APIs
- Simple UIs
- File operations
- External API integration

### L2 Capabilities
- Authentication/authorization
- Role-based access control
- Session management
- Security best practices
- Multi-tier architecture

### L3 Capabilities
- Microservices (5+ services)
- Event-driven architecture
- Real-time features
- Polyglot persistence
- Horizontal scaling

### L4 Capabilities
- Regulatory compliance
- Disaster recovery
- Multi-region deployment
- Complex business domains
- Platform architectures

## Quality Metrics Progression
| Aspect | L1 | L2 | L3 | L4 |
|--------|----|----|----|----|
| Functionality | Works | Edge cases | Resilient | Hardened |
| Security | Basic | Comprehensive | Defense-in-depth | Compliant |
| Scale | Small | Medium | Large | Enterprise |
| Architecture | Simple | Clean | Distributed | Platform |

## Common Use Cases
- **L1**: Personal projects, tools, converters, scripts
- **L2**: SaaS apps, e-commerce, CMS, team tools
- **L3**: Real-time platforms, marketplaces, analytics
- **L4**: Banking, healthcare, trading, enterprise systems

## Important Considerations
- Each level builds upon previous levels
- Higher levels include all lower level capabilities
- Progression requires mastering new skill domains
- Level selection affects all development phases
